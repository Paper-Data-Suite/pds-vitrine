# Vitrine v0.4.0 — Four-Phase Release Checklist

**Issue #117. Status: PREPARATION — NOT RELEASED.**

The historical `docs/release_checklist.md` is the frozen **v0.3.0** checklist;
this document governs **v0.4.0**. Do not overwrite or reinterpret past assets.

## Phase 1 — Preparation branch and PR

- [ ] Start from reconciled `main`, clean tree; record commit/tree.
- [ ] Create and use `release/v0.4.0`.
- [ ] Keep the Slice 1 historical hash ledger intact.
- [ ] Promote `vitrine/_version.py` and active package/CLI checks to `0.4.0`.
- [ ] Retain `pds-core>=0.6.5,<0.7` and optional producer dependencies.
- [ ] Prepare release notes, compatibility matrix, audit, and checklist.
- [ ] Reconcile current teacher and development installation instructions.
- [ ] Preserve archived v0.3.0 files and historical #71 acceptance exactly.
- [ ] Authenticate **official** Core/ScoreForm/Quillan/Concord release wheels.
- [ ] Verify exact current #103 audited filenames/hashes with `scripts/validate_issue117_release_wheels.py --wheel-dir`.
- [ ] Qualify installed v0.4.0 candidate against those exact wheels.
- [ ] Retain #104 future-version synthetic acceptance separately.
- [ ] Run full pytest, Ruff, strict MyPy, source/docs/package checks.
- [ ] Build candidate wheel/sdist and run Twine and installed-wheel smoke.
- [ ] Confirm full repository validation and supported GitHub CI pass.
- [ ] Review PR; merge only after required checks, with no unresolved blockers.

Run focused checks while implementing separate slices. Before PR merge, run
complete repository validation with an authenticated Core 0.6.5 wheel:

```powershell
python scripts/verify_core_wheel.py "$HOME\Downloads\pds_core-0.6.5-py3-none-any.whl"
python scripts/validate_repository.py `
    --core-wheel "$HOME\Downloads\pds_core-0.6.5-py3-none-any.whl"
```

The complete validator requires a **clean** checkout; `--allow-dirty` is for
focused development workflows, not final release qualification. Ensure no
stale repository-local `.egg-info` shadows installed distribution metadata.

## Phase 2 — Exact-main qualification (after PR merge)

- [ ] Reconcile `main` with `origin/main`; require clean working tree.
- [ ] Record exact release commit and tree SHA.
- [ ] Reauthenticate frozen official qualification input wheels.
- [ ] Run full repository qualification against exact clean `main`.
- [ ] Build exact final wheel and sdist and validate contents/metadata.
- [ ] Perform current official producer-wheel installed acceptance.
- [ ] Record exact SHA-256 hashes and create `SHA256SUMS.txt`.
- [ ] Recheck working tree and do not rebuild after hashing.

Expected publication assets:

```text
pds_vitrine-0.4.0-py3-none-any.whl
pds_vitrine-0.4.0.tar.gz
SHA256SUMS.txt
```

Any source correction after qualification requires a new PR and renewed
Phase 2 evidence. A candidate artifact is not itself a release.

## Phase 3 — Immutable publication

- [ ] Verify tag `v0.4.0` does not already exist.
- [ ] Create an immutable `v0.4.0` tag at the exact qualified commit.
- [ ] Publish GitHub Release `pds-vitrine v0.4.0` with reviewed notes.
- [ ] Attach only the exact Phase 2 wheel, sdist and checksum file.
- [ ] Do not move/rewrite the tag or silently publish to PyPI.
- [ ] Record tag, Release URL, and published asset identity in the audit.

## Phase 4 — Fresh-download verification

- [ ] Download all published assets into a **new** location.
- [ ] Independently verify downloaded hashes against Phase 2 and sums file.
- [ ] Install downloaded wheel noneditably with authenticated Core 0.6.5.
- [ ] Verify metadata, CLI, imports, Python floor, entry points and `pip check`.
- [ ] Verify standalone Core+Vitrine use without producers.
- [ ] Qualify relevant official producer readers from authenticated wheels.
- [ ] Verify Portfolio build, Presentation and historical sealed evidence.
- [ ] Record final release commit/tree, hashes, CI and fresh-download results.
- [ ] Only now declare `RELEASED — VERIFIED` and close issue #117.

## Cross-module and stop boundaries

A Vitrine-only package version increment does not authorize forced releases of
Core, ScoreForm, Quillan, Concord, Meridian or Portia. The Suite v0.1.0 exact
composition manifest is a separate, currently incompatible release authority.
Release stops on failed required tests/CI, unverified artifacts, metadata
disagreement, incompatible reader contracts, unauthorized source access,
immutable-custody failure, student-data leakage, version-only migration,
missing hashes, or failed fresh-download checks.
