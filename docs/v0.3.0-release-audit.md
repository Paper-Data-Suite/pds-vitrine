1. accepted ADRs;

3. merged implementation and executable tests;

with an accepted ADR or frozen producer contract is a blocker requiring a prerequisite

## Audit matrices still required before release verdict

Later #72 slices must explicitly disposition:

- ADR 0001 through ADR 0009;
- all #57 through #71 workstreams above;
- privacy: repository evidence, source-read/Artifact authorization, suppression,
  diagnostics, attention, backup, Snapshot/Export;
- provenance: identity, producer semantics, Candidate/Selection, curation,
  Composition, Snapshot, historical custody;
- usability: guided workflows, bounded diagnostics, consequential-decision visibility;
- package/runtime: Core-only dependency, entry points, wheel/sdist contents;
- exact live installed acceptance with the promoted `pds-vitrine 0.3.0` wheel;
- supported Ubuntu/Python 3.11 and Windows/Python 3.14 hosted gates.

## Known limitations carried into the audit

The release candidate intentionally does not claim production institutional
authorization, recipient/guardian verification, consent management, production
redaction/de-identification, external delivery/submission, operational regulated
Portfolio workflows, Meridian grading policy, ordinary Portia Portfolio exposure,
or suite-wide policy authority over Vitrine private records.

These are not release defects unless the merged code or release documentation falsely
claims them.
