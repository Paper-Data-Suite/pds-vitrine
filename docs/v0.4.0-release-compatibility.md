## Semantic runtime support is not artifact qualification

The existing Vitrine adapter/reader boundary consumes compatible public
`PublicationReaderSupport` / Core Reader Contract v1 declarations and the
underlying public producer reader. It does **not** equate the producer package
version or wheel digest with semantic compatibility. Unknown, malformed, or
unsupported reader metadata is rejected. Pre-metadata historical fallback is
bounded to exact accepted historical release identities.

| Producer | Public reader contract | Evidence custody |
| --- | --- | --- |
| ScoreForm | `scoreform_academic_result_reader_v1` | `reference_only`; distinct unranked attempts |
| Quillan | `quillan_academic_result_reader_v1` | copied student work only after separate Artifact authorization |
| Concord | `concord_academic_result_reader_v1` | copied source/feedback only after separate Artifact authorization |

The acceptance chain remains: Core discovery → canonical Publication reload →
producer registration and withdrawal/currentness → compatibility → explicit
source-read authorization → verified immutable manifest bytes → installed public
reader → pure Vitrine projection. Independent sealed Edition/Export verification
must not depend on producers remaining installed or their sources remaining live.

## Suite launcher boundary

The independent Paper Data Suite launcher v0.1.0 has a fail-closed exact-release
manifest qualifying Vitrine v0.2.0. That release does **not** automatically
qualify Vitrine v0.4.0. Updating its composition manifest requires separate Suite
integration and acceptance; it must not require unrelated producer releases
solely because Vitrine's version number changes.
